# Nimble Metric Exporter

The *Nimble Metric Exporter* is a process that sits in front of storage arrays that expose the
Nimble Rest API and monitoring platforms.

It harvests metrics and states from the API and processes them as Open Telemetry metrics for
consumption by upstream monitoring platforms.

Currently the only upstream monitoring system supported is Prometheus and metrics are exposed via a
Prometheus compliant scrape interface.  Other Open Telemetry exporters could be supported in the
future.

## Supported Arrays

Tested with an HPE Alletra 5050. However should work with:

* HPE Alletra 5000
* HPE Alletra 6000
* Any other array that exposes the Nimble Rest API *v1*

## References

The Nimble Rest API documentation is available here:

https://support.hpe.com/docs/display/public/nmtp352en_us/fhg1480349076889.html

## AI Usage Declaration

The API models under `internal/models` were initially generated by AI with a prompt instructing it
to generated Go types for the structures defined in the above reference.  They were then tuned by
hand to meet the requirements of this project.  They are internal to this project and should not be
trusted beyond the extent they are actually used by this project.

## Compared to the HPE Exporter

HPE provides a metrics exporter (https://hpe-storage.github.io/array-exporter/) however does not
expose any hardware related monitoring metrics.  For example, it won't tell you when a disk has
failed.

This exporter provides volume and pool utilisation similar to the HPE exporter, but also includes
hardware monitoring.

## Deployment

Options are:

1. Build from source and deploy the binary
1. Build a docker container and run the container
1. Deploy in Kubernetes along side the Prometheus operator.

The process requires in any case, requires the username and password to use to connect to any
storage platform.  These can be provided as command line options (`--username` and `--password`) or
as environment variables (`NIMBLE_USERNAME` and `NIMBLE_PASSWORD`).

The target storage platform host name is provided at scrape time with the `?target=<hostname>` query
parameter.  This allows for one process monitoring multiple arrays.

### Build from Source

```
$ go build -o ./bin/ ./...
$ ./bin/nimble_exporter --username myusername --password mypassword
```

Test with `curl http://localhost:9490/?target=myarray.mydomain.com`

### Docker

```
$ docker run --rm -p 9490:9490 chrisportman/nimble_metric_exporter:<version> --username myusername --password mypassword
```

### Kubernetes

See `./deploy/kubernetes.example.yaml` for an example set of manifests that includes among other
things:

* Storing the username and password in a secret and using it to populate environment variables in
  the pod.
* A ScrapeConfig for the Prometheus operator to consume.

At present, you will need to build and host your own container images.
